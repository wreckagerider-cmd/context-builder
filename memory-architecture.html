Escalation Path
Start at Step 1 and escalate only when the current layer demonstrably fails. Each step adds infrastructure cost and operational complexity.
1
Always start
File-system Prototype
Plain files with timestamps. Validates agent behavior before committing to any real infrastructure. Structured JSON facts are sufficient to test and iterate quickly.
Escalate when
Agent needs similarity search, or multi-tenant isolation that file lookups cannot handle.
2
Scale
Mem0 Vector Store
Move to Mem0 or a vector store with metadata when semantic search and multi-tenant isolation are needed. Pluggable backends let you swap the underlying store without changing agent code.
Escalate when
Retrieval quality degrades on relationship-heavy queries, or facts change over time and you need temporal validity.
3
Complex
Zep / Graphiti Temporal Knowledge Graph
Add Zep/Graphiti when the agent needs relationship traversal, temporal validity (bi-temporal modeling), or cross-session synthesis. Graphiti uses structured ties with generic relations — simple graphs, easy to reason over.
Escalate when
Agent needs to self-manage memory as first-class operations, or requires richer interconnected knowledge with dense relationship edges (Cognee).
4
Full control
Letta Cognee Full Self-managed Memory
Use Letta when the agent needs deep self-introspection through its Agent Development Environment. Use Cognee when the agent must build dense multi-layer semantic graphs — every core piece (ingestion, entity extraction, post-processing, retrieval) is customizable. Choose Graphiti for temporal bi-modeling; choose Cognee for richer interconnected knowledge.
Reached the top
Maximum infrastructure investment. Only justified when measured accuracy requires it.

Common Gotchas
Eight failure modes to avoid. Click each to expand the fix.
1
Stuffing everything into context
▼
Loading all available memories into the prompt is expensive and degrades attention quality. Large context payloads force the model to process irrelevant information on every token.
Use just-in-time retrieval with relevance filtering. Load memories only when they're needed for the current query, not proactively.
2
Ignoring temporal validity
▼
Facts go stale. Without validity tracking, outdated information poisons the context and the agent acts on wrong assumptions — silently, with no error signal.
Track valid_from and valid_until on any fact that can change over time. Use temporal filtering during retrieval.
3
Over-engineering early
▼
A filesystem agent can outperform complex memory tooling. Letta scored 74% vs Mem0's 68.5% on LoCoMo. Adding sophistication before you've measured a retrieval deficit wastes engineering time and adds operational burden.
Start with file-system. Add sophistication only when simple approaches demonstrably fail with measured metrics.
4
No consolidation strategy
▼
Unbounded memory growth degrades retrieval quality over time. As the memory store grows, relevant facts become harder to surface and retrieval latency increases.
Set memory count thresholds or scheduled intervals to trigger consolidation. Invalidate but don't discard — history matters for temporal queries.
5
Embedding model mismatch
▼
Writing memories with one embedding model and reading with another produces poor retrieval because vector spaces are not interchangeable. Similarity scores become meaningless across model boundaries.
Pin a single embedding model per memory store. If you change models, re-embed all existing entries before going live.
6
Graph schema rigidity
▼
Over-structured graph schemas (rigid node types, fixed relationship labels) break when the domain evolves. Adding new entity types requires schema migrations that touch existing data.
Prefer generic relation types and flexible property bags. New entity kinds shouldn't require schema migrations. Graphiti's approach: structured ties with generic relations.
7
Stale memory poisoning
▼
Old memories that contradict current state corrupt agent behavior silently. The agent confidently acts on outdated facts with no indication that anything is wrong.
Implement expiry policies or confidence decay so the agent deprioritizes aged facts. Surface contradictions explicitly when detected — prefer the most recent valid_from.
8
Memory-context mismatch
▼
Retrieving memories that are topically related but contextually wrong (e.g., a memory about "Python" the snake when discussing Python the language). Semantic similarity doesn't capture domain context.
Include session or domain metadata in memory entries and filter on it during retrieval. Don't rely solely on embedding similarity for disambiguation.
